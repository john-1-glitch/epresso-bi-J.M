# Project Reflection

Hayden and I originally planned to build this project together as a team, but we struggled to find a smooth way to split and coordinate the work across a single repository. Since I wanted to understand how the entire system came together rather than just handing off pieces, we decided that each of us would build and deploy our own complete application. I used Claude and Gemini as my AI development partners to build the E-Presso BI Analyst step by step, while also integrating Gemini as the live language model inside the application's analytical assistant.

My biggest analytical challenge was making sure the table joins could not silently distort revenue. The source files arrive in three formats—an Access database, a tab-separated CSV, and an Excel workbook—and at first glance the survey workbook looks like it should join directly to sales because both have store and year fields. Writing out the grain of each table exposed the trap: sales is one row per product, store, and month (25,200 rows), whereas the survey is one row per store per year (105 rows). Joining them would repeat every satisfaction score 240 times. Keeping Survey Results separate, joining only the many-to-one lookup tables, and wrapping each join in `check_merge()` guaranteed that all 25,200 rows and $42,174,440 in revenue remained intact before and after every merge.

The biggest technical challenge was making the assistant both accurate and reliable. Early testing showed that asking which store had the greatest percentage decline triggered a ranking of total revenue—a real calculation, but for the wrong question. Adding dedicated year-over-year comparison functions fixed that gap. Testing also revealed that Gemini's free tier allows only about 20 requests per model per day and occasionally times out while reasoning. I resolved this by increasing the request timeout, adding an automatic retry on a secondary model (`gemini-3.5-flash-lite`), and falling back to a deterministic rules-based router whenever the API quota is exhausted, displaying a clear badge on every answer showing whether Gemini or the rules engine responded.

AI was fast at generating boilerplate code, writing unit tests, and styling the interface into a sleek, modern dark-mode dashboard that preloads the default dataset while giving priority to user uploads. However, human judgment was essential to define business rules: deciding that "channel" maps to store type, keeping blank survey scores as missing rather than zero, refusing profit questions outright, and checking every number in Gemini's text against the tool output. I would trust this app for top-line revenue reporting because its numbers match Power BI and update instantly on the $1,000 test, but I would not trust it alone for store-closure decisions without cost, margin, lease, and customer-level data.
