# Project Reflection

Hayden and I originally planned to build this project as a team, but we could not find a clean way to split and coordinate the work across a single repository. Because I wanted to understand how the whole system worked rather than just handing off pieces, we decided to each build and deploy our own application. I used Claude and Gemini as my AI development partners to build the app step by step, and I connected Gemini as the live language model inside the analytical assistant.

My biggest analytical challenge was making sure table joins could not silently distort revenue. The source data comes in three formats: an Access database, a tab-separated CSV, and an Excel workbook. At first glance, the survey sheet looks like it should join to sales because both have store and year columns, but writing a grain statement for each table exposed the problem. Sales has one row per product, store, and month (25,200 rows), while the survey has one row per store per year (105 rows), so joining them would repeat every satisfaction score 240 times. Keeping the survey separate, joining only the many-to-one lookup tables, and wrapping each join in `check_merge()` guaranteed that all 25,200 rows and $42,174,440 in revenue stayed intact.

The biggest technical challenge was making the assistant both accurate and reliable. In early testing, asking which store had the greatest percentage decline triggered a ranking of total revenue, which was a real number for the wrong question. Adding year-over-year comparison functions fixed that gap. Testing also showed that Gemini's free tier allows only 20 requests per model per day and occasionally timed out while generating internal reasoning tokens. Disabling the extended thinking budget cut response times to about two seconds, and adding a backup model (`gemini-3.5-flash-lite`) plus a rules-based fallback ensured the assistant still works when quota runs out, with a badge on every reply showing whether Gemini or the rules engine answered.

AI was fast at writing code, building unit tests, and styling the sleek modern dark-mode interface that preloads default data while giving priority to user uploads. Human judgment was still essential to define the business rules: mapping channel to store type, leaving blank survey scores out rather than counting them as zero, refusing profit questions outright, and verifying every number in Gemini's text against the tool result. I would trust this application for revenue reporting because its totals match Power BI and update immediately on the $1,000 test, but I would not trust it alone to close a store without operating cost, margin, lease, and customer data.
